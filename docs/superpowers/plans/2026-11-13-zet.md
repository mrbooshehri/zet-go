# ZET implementation plan

**Goal:** Build an offline-first Markdown note manager compatible with existing timestamp directories.

**Architecture:** Shared note services own filesystem access, graph and search; CLI and TUI call the same services. Git and editors execute as argument arrays, never through a shell.

**Constraints:** Preserve Markdown and existing notes; Git is optional; no database; legacy commands remain available where practical.

- [ ] Establish compatibility baseline and project instructions.
- [ ] Implement and test note discovery, parsing, path validation and collision-safe creation.
- [ ] Implement and test graph extraction, backlinks, broken links, orphan detection and ranked search.
- [ ] Implement CLI and editor workflows with predictable errors and tests.
- [ ] Implement responsive Bubble Tea UI sharing application services.
- [ ] Implement scoped Git workflows, YAML configuration, documentation, CI and release tooling.
- [ ] Run formatting, build, tests, race detector and vet; audit compatibility and safety.

Dependency availability is an external constraint: the Go module proxy is inaccessible in the current sandbox. Avoid presenting incomplete work as a finished release.
